# Reporting SOP

## 1. Purpose
Standardize report creation, distribution, and review to ensure consistent data presentation and timely decision-making.

## 2. Scope
All recurring reports: daily dashboards, weekly summaries, monthly reviews, quarterly business reviews, and ad-hoc reports.

## 3. Prerequisites
- Access to data sources (CRM, analytics, financial systems)
- Report templates from `Templates/report-templates.md`
- Notion/Google Docs for report documentation
- Email distribution list configured

## 4. Procedure

### Step 1: Data Collection
```
1. Identify report type and frequency
2. Pull data from relevant sources:
   - CRM: Lead and pipeline metrics
   - Analytics: Website and content metrics
   - Financial: Revenue and expense data
   - Operations: Task completion rates
3. Verify data accuracy and completeness
4. Flag any anomalies or gaps
```

### Step 2: Report Creation
```
1. Select appropriate template from report-templates.md
2. Populate template with current data
3. Calculate key metrics:
   - Trend analysis (vs. previous period)
   - Goal tracking (vs. targets)
   - Variance analysis (vs. budget/forecast)
4. Add commentary on significant changes
5. Include visualizations where applicable
```

### Step 3: Quality Review
```
1. Verify all numbers match source data
2. Check calculations for accuracy
3. Ensure narrative matches data
4. Review for typos and formatting
5. Have a second pair of eyes review (if critical report)
```

### Step 4: Distribution
```
1. Format for distribution (PDF/email/web)
2. Send to distribution list per report type:
   - Daily Dashboard: Operations Team
   - Weekly Summary: Leadership Team
   - Monthly Review: All Staff
   - Quarterly BRD: Board/Investors
3. Post to shared drive/Notion
4. Archive previous period's report
```

### Step 5: Follow-Up
```
1. Schedule review meeting for quarterly reports
2. Track action items from report insights
3. Update forecast based on actuals
4. Adjust next period targets if needed
```

## 5. Quality Checks
- [ ] Data accuracy verified against sources
- [ ] All required metrics included
- [ ] Narrative supports the data
- [ ] Distributed on time per schedule
- [ ] Archived in correct location

## 6. Escalation Path
| Issue | Escalate To | Method |
|-------|------------|--------|
| Data source unavailable | IT/Source owner | Support ticket |
| Significant negative variance | Executive Team | Immediate briefing |
| Data discrepancy | Data owner | Direct message |
| Report deadline at risk | Manager | Advance notification |
